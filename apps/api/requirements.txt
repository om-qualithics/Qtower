# 1.98.0 (was 1.56.4; briefly 1.83.0, then 1.83.10) - two CVEs found across
# two rounds of re-scanning this repo with its own Code Scan feature:
#  - CVE-2026-35030 (GHSA-jjhc-v7c2-5hh6): OIDC-userinfo cache-key-collision
#    auth bypass in LiteLLM's proxy server, fixed in 1.83.0.
#  - CVE-2026-42208 (GHSA-r75f-5x8p-qvmc, CVSS 9.3, KEV-listed, exploited in
#    the wild ~36h after disclosure): SQL injection via a crafted
#    Authorization header against the proxy's API-key-check query, affects
#    1.81.16-1.83.6, fixed in 1.83.7 (1.83.10 is upstream's own recommended
#    "-stable" pin for that fix).
# Both vulnerabilities live entirely in the standalone LiteLLM *proxy
# server* - reachable only with enable_jwt_auth: true / the proxy's own
# DB-backed API-key auth, neither of which this app uses (litellm is a
# library dependency here, called directly via
# ai_gateway/providers/litellm_provider.py's litellm.completion(), never
# run as the standalone proxy) - so practical exposure was ~zero both
# times, but the vulnerable code was still shipping in the installed
# package, so upgraded rather than left as an accepted risk each time.
#
# Landed on 1.98.0 (latest stable), not the smallest CVE-clearing version
# (1.83.7/1.83.10), because of a real packaging conflict a *fresh* install
# hit that the native dev venv never surfaced (same class of gotcha as the
# old httpx<0.28.0 note this comment used to carry): every 1.8x litellm
# release hard-pins `click==8.1.8` and `importlib-metadata==8.5.0` exactly,
# which collides with semgrep's own transitive pins on those same packages
# (see semgrep's pin/comment below) with no version of either package able
# to satisfy both sides - a real `ResolutionImpossible` on a clean
# `pip install -r requirements.txt` (confirmed via a from-scratch, no-cache
# Docker build, not just the native venv). 1.98.0 switched both of those to
# ranges (`click<9.0,>=8.0.0`, `importlib-metadata<9.0,>=8.0.0`), which is
# what actually clears the conflict - a smaller litellm bump alone
# couldn't. httpx<0.28.0 is no longer required either (modern litellm only
# needs httpx>=0.23.0) - the old pin/comment for that constraint is gone.
# Full test suite (103 tests) and a from-scratch Docker build both
# re-verified green against this exact version pair.
